# GameShare

**English**: A lightweight Windows tool for 2–4 players to share their game windows
with each other over P2P WebRTC — everyone runs their own game locally and sees
everyone else's window in real time.

轻量级 Windows 多人游戏画面共享工具。

> 进房间 → 选游戏 → 开始共享 → 互相看画面。

2～4 人异地使用，各自跑自己的游戏，各自共享自己的游戏窗口，同时看到其他玩家的画面。
视频默认 WebRTC P2P 直连，声音按应用 / 整机 / 无声三态可选，浮窗模式可在全屏游戏上叠一层小窗。

## 项目现状

**v1.0（个人版）**——按「朋友间内部使用合格」的标准冻结。里程碑 M0～M6 全部完成
并各有自动化验收守护；M7～M10（网络状态面板 / TURN 中继 / 自动重连 / 性能压测）
暂不在当前计划内，详见 `docs/ROADMAP.md`。

- 2～4 人 Mesh，视频 P2P 直连（WebRTC），各路画面独立解码独立控制画质
- 游戏窗口捕获（推荐无边框窗口化；独占全屏不支持）
- **声音三态**：仅共享目标应用的声音（按进程树采集）/ 整机声音（排除本实例）/ 无声
- 每个远端的**语音与共享声分轨调音量**
- **浮窗模式**：缩成小窗压在全屏游戏上，不抢焦点，可拆成多枚独立小窗
- 双击放大单路 + 自动画质联动（放大那路 1080p，其余降档省上行）
- 200+ 项自动化验收：信令 17 项、链路出帧断言、音频频谱隔离度、三轨结构、
  浮窗层级与拆分各一组完整门禁

## 网络安全注意要点（先读这节）

这套工具**没有做鉴权**，把谁挡在外面完全靠「地址 + 房间码只有你自己人知道」。
所以这几条不是建议，是使用前提：

1. **公网地址绝不外泄。** 「异地访问」开关生成的 `https://*.trycloudflare.com`
   隧道地址，以及面板里显示的公网 IPv6 地址，**等于你家网络的公开入口**。
   只在私聊里发给要一起玩的人——**不要发进群、不要贴论坛、不要写进任何公开页面**。
   泄露的后果不是「多个人连进来」，而是任何拿到地址的人都可以用脚本爆破房间码
   （6 位码约 10.7 亿组合，服务端没有限流）。
2. **房间码同理，只在私聊里发。** 房间码是进房唯一凭证，猜中房间码的人
   **会立刻看到共享画面**——没有二次确认，也没有踢人功能。
3. **异地隧道用完立刻关。** 爆破需要时间，挂着的时间越短风险越小。
   挂一天和挂五分钟不是一个量级。客户端里的开关默认就是关的，保持这个习惯。
4. **局域网地址也别乱发。** `192.168.x.x` 地址只在你家网络内可达，
   风险低，但同样只发给一起玩的人。
5. **对称 NAT 打不通且没有兜底。** 任一方是对称 NAT 时直连失败，当前没有 TURN
   中继降级。表现为画面一直「协商中」。
6. 这套工具的威胁模型是「朋友间小圈子使用」。**想给陌生人 / 公开活动用，
   必须先自行加上鉴权与限流**（信令服务端是现成的 Node 服务，改造成本可控）。

## 快速开始（最终用户）

两台电脑都只需要装客户端，**不需要 Node.js，也不需要开命令行**。

### 同一局域网（默认场景）

1. 两台电脑都打开 GameShare。侧栏「本机信令服务」面板会显示运行状态
   和对方该填的地址（形如 `http://192.168.1.100:8080`）；
2. 首次启动 Windows 防火墙弹窗**必须点「允许访问」**——点成「取消」的话
   另一台会一直卡在「连接中」且两边都不报错（补救方法见故障排查）；
3. 在「信令服务器」框里填**对方面板显示的地址**，点「连接服务器」；
4. 一台点「创建房间」拿 6 位房间码，另一台输码「加入房间」。

> 两台都开客户端时，先启动的那台拿到 8080，后启动的显示「端口被占用」
> 并照常当客户端用——谁连谁由「信令服务器」输入框决定，不用管这个提示。

### 跨网络（异地）

客户端里打开「异地访问」开关（默认关），客户端会自己拉起临时隧道并显示
一个 `https://*.trycloudflare.com` 地址；点「复制邀请」把地址 + 房间码一次发给对方，
对方填进「信令服务器」框即可。**用完关掉开关。**

> 再次提醒：这个地址就是公网入口，见「网络安全注意要点」第 1 条。

打包版自带 `cloudflared.exe`，不需要手动下载；源码模式才需要
`tools/cloudflared.exe`（获取方式见 `docs/REMOTE-TESTING.md`）。

### 共享画面与声音

点「枚举窗口 / 屏幕」→ 选要共享的窗口（带缩略图）→ 对方画面上出现画面。
声音在共享面板上三选一（共享前、共享中都能改，共享中改会重采一次）：

| 模式 | 行为 |
| --- | --- |
| **仅此应用**（窗口源默认） | 只传选中窗口所属应用的声音（含直接子进程），别的提示音不会混进去。对整块屏幕源不可用，选了会明确落回「全部电脑」 |
| **全部电脑** | 传整机输出，但排除 GameShare 自己这个实例（自己这端播的队友声音不会被再采一圈送回去——这是衰减不是消除，仍建议共享时戴耳机） |
| **无声** | 不传声音，画面照常 |

采不到系统声音时**不会静默降级**：画面照常，弹出告警给你三个选择
（改用全部电脑 / 继续无声 / 取消共享）。

- 每个远端画面上都有「音量」按钮：**语音 / 共享声分开调**，只影响本机听感；
- 画面角落的「语音」「共享声」徽标实时标着这两路在不在传；
- 共享面板上的「关闭 / 开启应用声音」是暂时停发共享声（采集没停），与三态不同粒度。

### 看画面：双击放大

双击任意远端画面 → 放大铺满，其余收进底部缩略条；再双击或按 `Esc` 回网格。
放大自动联动画质（放大那路 1080p，其余 360p，还原回 540p）。

### 浮窗（全屏游戏时）

`Ctrl+Alt+G` 一键把正在共享的几路缩成小窗压在游戏上面：不抢焦点、可拖动、
可调透明度、可拆成各自独立的小窗。游戏请切**无边框窗口化**——
独占全屏既采不到也无法被覆盖，这是 Windows 侧限制。

## 从源码构建

环境要求：**Node.js ≥ 20**、Windows 10 / 11。

```bash
npm install            # 安装全部工作区依赖
npm run dev:desktop    # 启动客户端（Vite + Electron，改代码热更新）
```

不想开命令行，直接双击仓库根目录的几个 bat：

| 文件 | 做什么 |
| --- | --- |
| `run.bat` | 启动最新的已打包客户端（不构建、不安装，秒开） |
| `dev.bat` | 从源码跑（Vite dev server + Electron） |
| `build-exe.bat` | 一键打包，约 40 秒，结束时打印产物位置 |
| `diagnose-capture.bat` | 「窗口明明开着但列表里没有」的诊断工具 |
| `tunnel.bat` | 手动起异地隧道（客户端里已有开关，通常不需要） |

打包产物在 `apps/desktop/release/`：`GameShare Setup 1.0.0.exe`（安装包）
或 `win-unpacked/GameShare.exe`（免安装版）。

> bat 会在 `npm` 不在 PATH 时按 `GAMESHARE_NODE_DIR` 环境变量 → PATH 的顺序找
> node.exe。开发机特有的环境坑（npm 被拦截、electron-builder 缓存、产物目录
> 文件锁等）记录在 `docs/BUILD-NOTES.md`。

## 验收脚本

全部可无人值守判断通过与否：

```bash
npm run smoke              # 信令层 17 项：建房/进房/满员/防伪造/断线清理/心跳
npm run smoke:p2p          # 链路层：真实 Electron 跑 WebRTC，断言 getStats() 解码帧数在涨
npm run check:app-audio    # 应用级音频：真开窗口放测试音，FFT 量频谱隔离度（67 项）
npm run check:media-tracks # 三轨媒体结构 + 数字反馈环：4 窗口四人模型，两轮
npm run check:embedded     # 内置信令服务器：拿打包产物验（构建边界回归）
npm run check:standalone   # 独立部署产物：零依赖启动 + 双栈监听
npm run check:topmost      # 浮窗置顶与焦点（22 项）
npm run check:tiles        # 浮窗拆分模式（117 项，八组）
npm run check:network      # 本机 P2P 能力诊断（公网 IPv6 / NAT 类型，输出结论）
npm run check:stun         # STUN 节点体检（Chromium 侧能否拿到 srflx）
```

设计原则：断言写「实际值 == 按协议算出的期望值」；关键判据带**对照组**
（声音关掉再开回来必须听得见，否则只说明测量仪器聋了）；关键断言**反向验证过
确实会红**。`smoke:p2p` 的音频断言覆盖的是合成源，真实系统声音由
`check:app-audio` 单独覆盖；「共享真实游戏窗口带没带声音」只能实机听。

## 已知限制

1. **独占全屏不可捕获**（Windows 侧限制），游戏请切无边框窗口化；
2. **对称 NAT 无法直连且无 TURN 兜底**（M8 未做）；
3. **信令无鉴权**，见「网络安全注意要点」；
4. 部分内核级反作弊（EAC / BattlEye / Vanguard）会对屏幕采集做额外判定，
   使用前自担风险，建议先拿无反作弊的游戏试；
5. 只有 Windows 能采系统声音（按应用 / 整机两态依赖 Windows 进程树回环采集）。

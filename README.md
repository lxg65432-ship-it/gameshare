# GameShare

> [English](README.en.md) | 简体中文

> **为游戏而生，不止于游戏。**
> 与身在千里之外的朋友，获得天涯若比邻的开黑体验。

![GameShare 主窗口](docs/screenshots/main-window.png)

![浮窗模式：小窗压在全屏游戏上](docs/screenshots/float-overlay.jpg)

几个朋友，各自在家打自己的游戏，但想互相看到对方在玩什么——这就是它做的全部事情。

开一个房间，把邀请发给朋友，朋友粘贴一下就进来了。然后每人选自己的游戏窗口开始共享：
互相看画面、开语音、听得到对方的游戏声音。2～8 人，画面走 WebRTC 直连，不经过中间服务器。
8 人是架构余量（Mesh 直连的实际上限）：日常开黑 3～5 人最舒服；人越多，
每个人要发送的路数越多（8 人 = 每人同时发 7 路 ≈ 42Mbps 上行 + 7 路硬编码），
网络或显卡撑不住时画面会先卡——实际用多少人，取决于你们的上行带宽。

当前版本 v1.3.0。后续计划（以及几件明确不做的事）见 `docs/ROADMAP.md`。

## 功能

- **一键邀请**：房主点「复制邀请」，朋友把收到的整段文本粘进房间码框，自动连接、自动进房——地址、房间码都不用手填
- **窗口共享**：带缩略图的窗口列表，选中即共享。独占全屏抓不到（Windows 的限制）；游戏不支持无边框窗口化时，列表里的「无边框化」按钮可以强制转换，再点一次还原
- **声音三选一**：只共享目标应用的声音（按进程采集，提示音不会混进来）/ 共享整机声音（不含本软件自己播放的）/ 无声。共享前后都能切
- **分轨音量**：每个朋友的语音和游戏声分开调，只影响自己这边听到的
- **浮窗模式**：`Ctrl+Alt+G` 把画面缩成小窗压在全屏游戏上，不抢鼠标焦点，可拖动、调透明度，也能把每路画面拆成独立小窗各自摆放
- **双击放大**：任意一路铺满全屏，其余收进缩略条，画质自动跟着调整
- **共享帧率可选**（30 / 60 / 120），码率按画面内容自适应——2K、带鱼屏不会被压成低清
- **中英双语**界面，顶栏一键切换，重启后保持

## 安全须知（用之前读一遍）

这个工具没有账号和鉴权：能不能进房间，取决于房间码有没有泄露。所以——

1. **隧道地址别外泄。** 「异地访问」开关生成的 `https://*.trycloudflare.com` 地址，
   就是你家网络的公网入口，只在私聊里发给要一起玩的人。不要发群、不要贴论坛、
   不要写进任何公开页面。房间码 6 位、约十亿种组合，服务端没有限流，
   地址一旦泄露，别人有充足的时间慢慢试。
2. **房间码同理，只在私聊里发。** 猜中房间码就能直接看到画面——没有确认步骤，也没有踢人按钮。
3. **异地隧道用完就关。** 开着的时间越短，留给别人的窗口越小。这个开关默认是关的，保持这个习惯。
4. **想给陌生人用？先加上鉴权再说。** 现在的设计只适合彼此信任的小圈子。
   信令服务端是现成的 Node 服务，改造起来不算难。

局域网地址（`192.168.x.x`）只在你自己的网络内可达，风险低，但同样只发给一起玩的人。

## 快速开始

两台电脑都装客户端就行，不需要 Node.js，不用碰命令行。

**第一次启动时 Windows 防火墙会弹窗，点「允许访问」。** 点成「取消」的话，
另一台会一直卡在「连接中」，两边都不报错——这是最容易踩的坑。

### 同一局域网

1. 房主打开 GameShare，在「本机信令服务」面板点**启用**，再点**创建房间**；
2. 点房间码旁的**复制邀请**，把那段文本发给朋友（微信、QQ 都行）；
3. 朋友把收到的整段文本**粘进房间码框**——地址自动填、自动连接、自动进房。
   想自定义昵称，粘贴前先填好。

> 同一台电脑先启动的客户端会占用 8080 端口，后启动的提示「端口被占用」——不用管，照常用。
> 手动填地址的老办法收在「网络设置」折叠里。

### 跨网络（异地）

房主打开「异地访问」开关，等客户端自己拉起隧道（打包版已内置 cloudflared，
源码运行才需要 `tools/cloudflared.exe`，见 `docs/REMOTE-TESTING.md`）。
之后流程一样：创建房间 → 复制邀请 → 发过去，对方粘贴即进。**玩完把开关关掉。**

### 共享画面和声音

进房后点「枚举窗口 / 屏幕」，从列表里选要共享的窗口。声音三选一：

| 模式 | 效果 |
| --- | --- |
| **仅此应用**（窗口源默认） | 只传这个应用（含其子进程）的声音，微信提示音之类不会混进去。整屏源用不了这个模式 |
| **全部电脑** | 传整机声音，但排除 GameShare 自己。对回声的抑制有限，共享时建议戴耳机 |
| **无声** | 只传画面 |

采不到声音时它不会自己换个模式凑合：画面照常开，弹提示让你选
（改用全部电脑 / 继续无声 / 取消共享）。

每个远端画面角上有「音量」按钮，语音和游戏声分开调；「语音」「共享声」两个小徽标
实时标着对方现在传没传这两路声音。

### 看画面

双击任意一路放大铺满，其余收进底部缩略条；再双击或按 `Esc` 回来。放大的那路画质
自动提上去，其余自动降下来省带宽。

### 浮窗（全屏游戏时）

按 `Ctrl+Alt+G`：正在共享的几路画面缩成小窗压在游戏上面，不抢鼠标焦点，可拖动、
调透明度，也能拆成每路一个独立小窗。游戏需要是**无边框窗口化**——独占全屏
既抓不到也盖不住，这是 Windows 的限制。

## 从源码构建

环境要求：**Node.js ≥ 20**、Windows 10 / 11。

```bash
npm install            # 安装全部工作区依赖
npm run dev:desktop    # 启动客户端（Vite + Electron，改代码热更新）
```

不想开命令行，直接双击仓库根目录的几个 bat：

| 文件 | 做什么 |
| --- | --- |
| `run.bat` | 启动最新的已打包客户端（不构建、不安装，秒开） |
| `dev.bat` | 从源码跑（Vite dev server + Electron） |
| `build-exe.bat` | 一键打包，约 40 秒，结束时打印产物位置 |
| `diagnose-capture.bat` | 「窗口明明开着但列表里没有」的诊断工具 |
| `tunnel.bat` | 手动起异地隧道（客户端里已有开关，通常不需要） |

打包产物在 `apps/desktop/release/`：`GameShare Setup 1.3.0.exe`（安装包）
或 `win-unpacked/GameShare.exe`（免安装版）。

> bat 会在 `npm` 不在 PATH 时按 `GAMESHARE_NODE_DIR` 环境变量 → PATH 的顺序找
> node.exe。开发机特有的环境坑记录在 `docs/BUILD-NOTES.md`。

## 验收脚本

这个项目的功能都带着能自动判断通过与否的验收脚本：

```bash
npm run smoke              # 信令层 17 项：建房/进房/满员/防伪造/断线清理/心跳
npm run smoke:p2p          # 链路层：真实 Electron 跑 WebRTC，断言解码帧数在涨
npm run check:app-audio    # 应用级音频：真开窗口放测试音，FFT 量频谱隔离度（67 项）
npm run check:media-tracks # 三轨媒体结构 + 数字反馈环：4 窗口四人模型，两轮
npm run check:embedded     # 内置信令服务器：拿打包产物验（构建边界回归）
npm run check:standalone   # 独立部署产物：零依赖启动 + 双栈监听
npm run check:topmost      # 浮窗置顶与焦点（22 项）
npm run check:tiles        # 浮窗拆分模式（117 项，八组）
npm run check:network      # 本机 P2P 能力诊断（公网 IPv6 / NAT 类型，输出结论）
npm run check:stun         # STUN 节点体检（Chromium 侧能否拿到 srflx）
```

这些脚本的设计思路：断言只写机器能判定的等式；关键判据带对照组（声音关掉再开回来
必须听得见，不然只能说明测量本身坏了）；每个关键断言都反向验证过——故意制造失败，
确认它真的会红。`smoke:p2p` 覆盖的是合成源，真实系统声音由 `check:app-audio`
单独覆盖；「共享真实游戏窗口带没带声音」只能实机听。

## 已知限制

1. **独占全屏不可捕获**（Windows 侧限制），游戏请切无边框窗口化；
   游戏不支持时可用源列表里的「无边框化」按钮强制转换（再点一次还原）——
   该功能只调 Win32 窗口 API、不碰游戏进程，但个别游戏会自己改回窗口样式而无法生效；
2. **对称 NAT 无法直连且无 TURN 兜底**（M8 未做）；
3. **信令无鉴权**，见「安全须知」；
4. 部分内核级反作弊（EAC / BattlEye / Vanguard）会对屏幕采集做额外判定，
   使用前自担风险，建议先拿无反作弊的游戏试；
5. 只有 Windows 能采系统声音（按应用 / 整机两态依赖 Windows 进程树回环采集）。
